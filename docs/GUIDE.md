# wxhook-api

基于 FastAPI 的微信 Hook HTTP 桥接与本地群聊管理系统，提供群聊和成员同步、聊天记录归档、@机器人问答、分享解析、关键词规则及定时提醒。
目标微信版本为 **WeChat 4.1.10.27**，需要配合已安装的 Hook 使用；接口契约见 `默认模块(1).md`。

> 本文件是完整手册。[README](../README.md) 只保留快速开始和文档索引；历史审查快照在 [reviews](reviews/README.md)。

## 快速开始

准备 Windows、Python 3.11 或更高版本，以及已配置 Hook 的微信客户端。在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe main.py
```

首次启动前，将 `launcher.yml` 中的 `wechat-path` 改为本机 `Weixin.exe` 路径，并确认 Hook DLL 与其配置位于微信主程序同目录。
服务就绪后会自动打开管理页面；微信未登录或 Hook 暂不可用时，页面仍可打开并等待连接。安装和路径配置详见[安装](#安装)与[一键启动说明](#一键启动微信hook-和聊天页面)。

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:8000/` 或 `/manage` | 群聊、成员、功能配置、聊天记录与群工具 |
| `http://127.0.0.1:8000/messages` | 手动收发文本、检查连接与回调 |
| `http://127.0.0.1:8000/douyin` | 分享解析设置、任务进度与本地媒体 |
| `http://127.0.0.1:8000/docs` | OpenAPI 交互文档 |

新发现的群默认不开启自动功能，需在管理页明确启用；AI 问答和报表需另行配置模型。历史导入仅归档，不补答旧问题或重新解析旧链接。

## i5-3470 / 8GB / 256GB / H61 运行说明

这套硬件以单个微信客户端、本地桥接服务和一个管理页为部署起点。项目通过 HTTP 调用模型，不包含本地大模型推理。最终承载量取决于活跃群数、消息频率、历史记录和媒体下载量；以下是按代码行为给出的起始配置，尚未在这台机器上实测 CPU、内存或吞吐量。

- 使用 `main.py` 默认的单进程启动。回调最多 4 个会话并发处理，同一群或私聊保持顺序；AI 调用最多两个并发，媒体下载串行执行。不要因为四核就改成四个服务进程，各进程会各自启动同步和调度任务。
- 管理页消息约每 3 秒刷新，词云和雷达约每 30 秒刷新；手动刷新立即重新请求统计，切群、统计天数变化、机器人身份变化和北京时间跨日会重新加载。隐藏标签页暂停轮询。
- 成员名单按差量更新，名单未变化时不改写成员行；雷达用整数计算日期与小时统计，减少大量历史消息的日期转换开销。合成数据对比中，10 万条消息雷达统计约快 1.75 倍，50 个群、每群 400 名成员的重复同步约快 1.48 倍，实际收益取决于记录量和名单变化情况。
- 数据库启动时自动补建当前成员和黑名单成员索引，后续启动复用；原查询和业务行为保持一致。在 10 万名成员的合成数据中，群列表、黑名单列表、权限重载耗时分别减少约 19%、25%、28%，新增索引约 1.68 MiB。
- 全量历史首次导入会持续读写本地数据库。正常同步默认间隔 60 秒；如目标机磁盘持续繁忙，可在启动前设置下面的环境变量，把正常轮询间隔调到 180 秒。首次导入未完成、连接失败等重试仍保持原有 5 秒间隔，实时回调不受此设置影响。
- 256GB 是总容量，不等于可用空间。媒体默认单文件上限 100MB、单作品累计上限 500MB；已回传媒体保留 24 小时，其他媒体保留 72 小时，记录保留 30 天，每天定时清理，因此不是磁盘总配额。聊天归档数据库没有自动过期删除，需要持续观察实际增长；本次检查没有清理已有聊天或媒体。

可选的 PowerShell 启动设置（仅作用于当前窗口及它启动的服务）：

```powershell
$env:WXHOOK_SYNC_INTERVAL = '180'
.\.venv\Scripts\python.exe main.py
```

`.env.example` 是变量示例，启动器不会自动读取 `.env`；在 PyCharm 运行时应把变量填入运行配置。目标机验收时，同时观察任务管理器中的 Python、微信、浏览器内存和 CPU，以及磁盘活动时间；分别检查空闲、实时消息、首次历史导入和媒体下载场景，不能仅用群数量判断容量。

`WXHOOK_CALLBACK_WORKERS` 控制回调并发，默认 `4`，允许 `1` 至 `4`。这是单进程中的异步处理链数，不是固定的操作系统线程数或 CPU 核数。不同群等待微信账号核验、数据库或其他异步操作时可以交错推进；同群顺序、归档先于自动处理、数据库写入串行和有界队列均保留。跨群完成顺序可能变化，单群持续发消息不会因这个设置获得四倍处理能力。如目标机 Hook 在并发请求下出现超时，可先设为 `2`，或设为 `1` 恢复全局串行，然后重启服务。

可运行 `.\.venv\Scripts\python.exe -m tests.benchmark_callbacks` 重现纯模拟等待的对比。本次 120 条回调、8 个会话、每条模拟 20 毫秒等待：单路 3.235 秒，四路 0.836 秒，约 3.87 倍。这个结果仅验证等待能重叠，不代表真实微信吞吐量或 CPU 性能；首次历史同步、模型调用和媒体下载不由这个回调并发开关加速。

## 微信风格的群聊管理系统

在 PyCharm 运行根目录 `main.py`，服务就绪后会自动打开浏览器访问管理系统 **`http://127.0.0.1:8000/`**（或 `/manage`），默认不主动唤起微信窗口。
首页现为群聊管理工作台，原来的消息收发工具移到 `/messages`，分享解析资源页面仍在 `/douyin`。
不需要安装前端工具或额外的数据库服务。

- 微信登录后自动通过只读数据库查询同步全部可读取群聊，不受联系人搜索 20 条上限影响；左侧支持搜索、运行状态筛选、置顶和手动添加。
- 点击左侧任意群聊，中间直接打开消息窗口，按时间从上到下显示消息并定位到最新一条；自己的消息显示为右侧绿色气泡。
- 管理页消息窗口用于查看群消息，消息区占满中间空间。
- 左侧绿色群聊表示机器人已启用，灰色表示未启用，浅红表示已拉黑，并显示对应文字状态。判断依据为群功能总开关、分享解析或 @问答开关及黑名单的实际生效状态。
- 已启用机器人的群聊优先显示；同一状态内保留置顶、最近活跃的排序规则。可筛选已启用、未启用或已拉黑的群。
- 搜索与历史翻页位于消息窗口上方；阅读旧消息时按消息 ID 保持阅读位置；如果当前内容已被新消息挤出最新页，会暂时保留当前内容，可点“回到最新消息”更新。功能配置、成员与黑名单管理入口仍保留。
- 自动同步可读取的完整群成员关系和微信名称；不兼容的成员表会标记为“部分发现”，不会假装完整。历史成员和手动添加记录会保留。
- 每个群可分别开启“@机器人问答”“分享解析”和“自动保存视频与图片”；群功能总开关可暂停该群全部自动功能并保留设置。
- 群聊可加入或移出黑名单；成员黑名单仅在对应群生效，不影响其在其他群的功能使用。成员搜索框在后台刷新时保持输入焦点。
- 群名称和成员名称默认跟随微信同步；自定义名称、备注、功能开关和黑名单不会被同步覆盖。清空本地名称可恢复跟随微信。
- “群消息”可查看持久化聊天记录，支持全文搜索与翻页；左下角可检查连接、启用消息接收，顶部可查看进度并立即同步。

**黑名单停止的是本系统自动处理，不会退出微信群、踢出成员或屏蔽微信消息。**
拉黑或暂停后，新消息不再触发解析；正在解析的任务会在解析返回后检查限制，下载在下一个数据块检查并停止，未完成文件会清理。
群消息仍可以记录并在“群消息”查看。已保存文件不受影响。

管理配置、群与成员、完整聊天记录、历史导入断点及最近 500 条操作记录保存在项目 `data/management.sqlite3`，重启保留，已忽略 Git。
可用 `WXHOOK_MANAGEMENT_DB` 指定数据库路径。默认启用在线自动备份，配置和恢复方法见下方“长期运行与故障恢复”。手动直接复制原数据库文件时仍需先停止服务。
原 `/messages` 收发工具仍只展示进程内最近 100 条回调；管理系统的“群消息”使用持久化记录，不受此上限影响。

### 自动同步与聊天记录

自动同步默认开启，直接运行 `main.py` 即可。微信未登录或 Hook 暂时断开时，服务等待并自动重试，已保存记录仍可离线查看。
首次登录后读取群聊与成员名单，再分批调用 `/Message/history` 导入当前电脑微信本地可读取的全部群历史；每批每群最多 5 页、每页 200 条，未完成的群自动续传，没有总记录条数截断。
完成首次导入后默认每 60 秒刷新名单和增量消息；导入未完成或连接中断时每 5 秒继续尝试。
顶部状态条显示当前群与进度，“立即同步”只安排同一个后台任务，不会重复启动导入。

实时群回调同时写入资料库；历史与回调有相同非零消息 ID 时合并，ID 以字符串保存，避免大整数精度丢失。
没有服务端 ID 的历史记录按来源数据库、本地 ID 等信息识别；没有有效 ID 的实时回调独立保存，可能与无有效 ID 的历史记录同时存在。
历史导入只归档，不进入自动功能处理队列，因此不会重新解析旧分享链接或重复下载旧媒体。
黑名单只控制自动功能，不影响聊天记录归档。

同步范围是**当前电脑的微信本地可读数据**，无法取回微信本机已删除、未同步到本机或仅在其他设备上的消息。
图片、语音、文件等消息保存接口返回的文字/XML 与原始字段，不批量下载聊天附件。
群名册使用表和字段探测，支持 `contact / chat_room / chatroom_member` 关联关系与旧版 `ChatRoom.MemberList`；不支持的成员二进制格式会明确提示。
适配时参考了[公开数据库结构说明](https://github.com/bojieli/greenbubbles/blob/main/docs/WECHAT_DATABASE_FORMAT.md)，实际是否可读取仍以测试机 Hook 返回的表结构为准。

旧管理资料库会自动增加所需表和字段，保留已有配置。同步只添加或更新资料，不删除本地群档案或已保存历史。
首次确认登录账号后会绑定当前微信账号；如果切换账号，自动同步和群回调归档会拒绝写入同一资料库。
账号不一致会同时暂停全部群的自动问答、关键词回复、媒体处理和自动发送，关键回调校验失败后不会继续执行后续处理器。即使关闭后台同步或手动配置机器人 wxid 与昵称，启用了自动功能的群仍会核验账号；排队任务、群资料的模型请求和微信发送前也会重新核验。
检测到账号变化后，暂停状态保持到服务重启，管理页显示账号变化提示；切回原账号后请重启服务。
新账号请设置独立 `WXHOOK_MANAGEMENT_DB` 后重启，避免混合两个微信账号的聊天记录。

可选环境变量：`WXHOOK_SYNC_ENABLED=false` 关闭后台同步；`WXHOOK_SYNC_INTERVAL=60` 设置增量同步间隔（秒，最小 5）。
系统中没有运行微信 Hook 时可使用模拟接口进行自动化测试；真实群名、完整成员关系和本机历史覆盖范围仍需在登录微信的测试机验收。

已有 `douyin.yml` / `douyin.local.yml` 中的群名单会自动加入管理列表。
尚未单独修改的群沿用旧解析设置；在管理系统明确设置过的功能开关优先于 `/douyin` 的默认配置。
新发现或手动添加的群默认不开启解析，需要自行打开，已拉黑的成员和群始终受限。

### 群工具：报表、关键词规则与待办

选择群聊后打开 **「群工具」**：

- **周报 / 月报**：生成上一完整自然周（周一至周日）或自然月的总结。可手动刷新，或单独开启自动生成；后台每分钟检查，启动后会补生成上一期，已保存的非空报表不会反复调用模型；空报表会在下次查询或自动调度时重新检查已导入的历史记录。阅读中展开的报表会在页面刷新后保持展开。报表保存本机，不主动发送到群里。在启用 @问答的群内发送 `@机器人 周报` 或 `@机器人 月报` 可获取。模型输入最多选取最近 800 条成员文本，并限制总长度；界面显示实际选取条数。
- **关键词规则**：每群最多 50 条，支持包含/完全匹配（忽略英文字母大小写）、记录命中或固定回复，冷却 10～86400 秒。新规则默认关闭；同一消息按规则名称与 ID 顺序只触发第一条匹配规则；出队时重新匹配当前规则，发送前再次核对关键词、匹配方式和回复内容，避免编辑规则后对旧消息误回复。优先于媒体解析，@问答优先于规则。只处理新的实时文字消息，不补处理历史记录；遵循群总开关、群与成员黑名单，并排除机器人消息。发送前持久化占位，发送未确认也不自动重发，页面保留最近 30 条命中结果。命中日志每群最多保留 500 条。
- **群待办**：群成员通过 @机器人创建的定时提醒会自动进入待办；保留手动新增、编辑，以及由当前模型从最近 7 天最多 200 条成员文本提取候选项并核对保存的功能。候选按群保留在当前页面中，可逐条保存、返回列表或关闭后继续核对；刷新或关闭浏览器页面会清空未保存候选。页面按 **未完成 / 已完成 / 已取消** 分开展示，每页25条，可翻页查看全部。记录来源、创建者、创建时间、负责人、精确到秒的截止时间及完成时间；每条未完成待办显示实时倒计时，到截止时间后由后台每秒检查并自动移入“已完成”，页面显示“到期自动完成于”。无截止时间的事项仍保留未完成，显示“未设置截止时间”。群提醒的创建者为发起成员，网页新增及保存 AI 候选的创建者为“本地管理员”；旧待办无法还原的创建者标为“未知（历史记录）”。仅有截止日期的旧待办和 AI 候选按北京时间当日23:59:59截止。群提醒到期时仍会 @发起成员发送提醒；完成状态与提醒发送状态分别记录，即使微信暂不可用，待办也会按时自动完成，发送恢复后仍遵守原有去重策略。手动提前完成或取消待办会停止尚未发送的提醒，群内取消提醒也会同步取消待办。重新打开未来截止的已停止提醒会恢复计时；已过期的条目重新打开后会再次自动完成。将到期自动完成的事项修改到未来截止时间会恢复为未完成，群提醒会按新时间重新安排。每群最多保留1000条未完成待办；已完成和已取消的记录保留且不占用此额度，重新打开或将自动完成事项延期时也会检查额度。可单独开启每日到期汇总，北京时间每天09:00后汇总到期自动完成且尚未汇总过的手动 / AI 待办，最多20条、每群每天最多尝试发送一条，每条事项最多参加一次汇总，群提醒不重复参加每日汇总。服务需保持运行，重启不补发已尝试的汇总，未处理的过期任务会在启动后自动完成。在启用 @问答的群里也可查询 `@机器人 本群待办`、`@机器人 到期待办`；到期待办包含到期自动完成的事项，按最近到期优先展示，排除手动完成和已取消事项。旧提醒会在启动时自动导入待办，重复重启不重复导入。
- **成员定时提醒**：在启用 @问答的群内发送 `@机器人 提醒一分钟后喝水`，机器人确认记录，到时间后在原群真正 @发起成员并发送事项。无需配置 AI 模型，也无需开启待办的每日到期提醒。支持 `提醒我10分钟后开会`、`半小时后提醒我休息`、`提醒我一小时三十分钟后交报告`、`提醒我明天09:30交报告`；支持秒、分钟、小时、天和今天/明天/后天的 `HH:mm`，均按北京时间，范围为1秒至365天。未写日期的时刻取下一次该时刻。发送 `@机器人 我的提醒` 查询本群自己的待提醒事项（最多展示20条），发送 `@机器人 取消提醒 编号` 取消。每人每群最多50条待提醒，每群最多200条。服务每秒检查；微信和服务需保持运行，实际发送受队列及接口耗时影响。提醒持久化，重启后会补发仍待发送的过期提醒；同一回调不重复创建，发送失败或结果不明不自动重发。到点时群或成员被拉黑、群功能或该群 @问答关闭，则跳过该提醒；全局问答关闭时暂停检查，恢复后继续。仅处理实时群内 @消息。

“一分钟后”等相对提醒从提醒实际写入数据库的创建时间开始计时，排队等待不占用倒计时，秒数不会取整到分钟。例如23:26:45创建的一分钟提醒，到期时间为23:27:45。机器人确认回复会显示准确到秒的到期时间。

报表与 AI 待办提取复用已配置的当前 AI 模型；所选群的文本样本会发送到该模型。雷达统计、关键词规则和手动待办不调用模型。报表、规则、命中记录、待办和提醒状态均保存于管理资料库，重启保留；自动报表与到期提醒默认关闭。

群工具接口前缀为 `/api/manage/groups/{群ID}/tools`：`GET` 读取状态，`PATCH /preferences` 设置 `auto_reports` 与 `task_reminders`；`POST /reports/week`、`POST /reports/month` 刷新报表；`POST /rules`、`PUT /rules/{ID}`、`DELETE /rules/{ID}` 管理规则；`POST /tasks/extract` 提取候选项、`POST /tasks` 保存待办、`PUT /tasks/{ID}` 编辑事项、负责人及截止时间，`PATCH /tasks/{ID}` 更新 `status`（`open` / `done` / `cancelled`）。新增和编辑支持 `due_at`（ISO日期时间，缺少时区时按北京时间解释）或旧版 `due_date`（YYYY-MM-DD）；返回的待办 `due_at` 为Unix秒数，创建者和完成时间由服务端记录，不能由请求伪造。

### 群聊梗百科、爬楼助手与聊天变漫画

在管理页选中群聊，进入 **群工具 → 群聊趣味工具**，可打开三个工具。网页生成的结果只在弹窗中展示，不主动发送到微信群；漫画可预览和下载。网页结果未保存为长期百科条目，关闭弹窗前请复制正文或下载图片。

群内使用需开启全局问答、本群功能及本群 **@机器人问答**，并明确 @机器人：

| 指令 | 用途 |
| --- | --- |
| `@机器人 梗百科：周三战神` 或 `@机器人 “周三战神”是什么梗` | 从本群归档中搜索关键词，结合早期上下文解释含义、演变及用法，附来源原话和编号。只把最早记录称为“本机归档中最早出现”，证据不足时说明，不能据此认定真正起源。 |
| `@机器人 爬楼` | 回顾北京时间今天的成员文本，按话题整理重要结论、待办和未解决问题。 |
| `@机器人 爬楼 最近2小时` | 回顾指定时间段；支持分钟、小时、天，也支持“最近两小时”“最近半小时”。最长7天，默认最多200条。 |
| `@机器人 爬楼 从消息123之后` | 按消息时间和编号选取该消息之后、最近7天内的记录；编号使用管理页消息旁的 `#123`，不是微信原始 msgid。 |
| `@机器人 聊天变漫画` | 取今天最近50条成员文本，由对话模型写四格分镜，再调用生图模型生成一张漫画并回传原群。 |
| `@机器人 聊天变漫画 最近30条` | 取最近7天内最多30条；漫画最多100条。也可用“最近2小时”等时间范围。 |

网页可选择时间范围、最多条数、起始消息编号，或填写逗号分隔的消息编号，仅分析指定记录。起始编号与指定编号不能同时填写；指定消息仍须位于所选时间范围，且属于当前群。来源原话会显示编号、时间和成员，可用于核对结果。梗百科最多选取最早80条命中及最早命中附近的上下文，不限制在最近7天。

三个工具都只读取本群本机已归档的成员文本，排除机器人、自发消息和当前黑名单成员；群暂停、账号异常或参与分析的成员被拉黑时，后续生成和发送停止。文本样本只发送给已配置的对话模型，不使用联网搜索或普通问答上下文。输入长度有上限，页面显示实际取样条数；爬楼不保证覆盖全部聊天。模型返回的来源编号须来自实际送入模型的记录，无法核对时拒绝返回结果。

梗百科和爬楼需要对话模型；漫画还需要生图模型，分镜及生图分别计入原有模型额度，可能产生服务商费用。漫画使用虚构角色，是创意改编；模型对人物和文字的呈现可能不准确。网页不会自动重试生成；群内沿用一条提问最多一次发送尝试和消息去重策略，重启不补生成。

接口：`POST /api/manage/groups/{群ID}/insights/{meme|catchup|comic}`，请求支持 `term`、`window`（默认今天）、`limit`、`after_id`、`message_ids`。响应含 `text`、`message_count`、`sampled_count`、`sources`，漫画另含 `image_data_url`（PNG Base64）。网页接口是管理员手动生成入口，遵守群总开关、黑名单及账号核验；群内命令另外遵守 @问答开关。

## 群内生图与生图模型配置

打开管理页左侧 **「AI 模型 → 生图模型 → 添加生图模型」**，填写配置名称、Base URL、完整模型 ID、API Key 和图片尺寸。生图模型与对话模型分别保存、分别启用；可以保存多个生图配置，同时启用一个。

- 接口使用兼容 OpenAI 的非流式 `POST /images/generations`，地址通常以 `/v1` 结尾，也可直接填写完整生图地址。支持 `data[0].b64_json` 和 `data[0].url` 返回，接口字段参考 [OpenAI Images 官方文档](https://developers.openai.com/api/reference/resources/images/methods/generate)。仅支持此接口协议，暂不支持 Chat Completions 生图、异步任务轮询和图生图。
- 图片尺寸默认 `1024x1024`，可填写服务商支持的其他尺寸（边长不超过 4096）、`auto` 或留空；留空时不发送尺寸参数。返回格式默认跟随服务，也可指定 Base64 或 URL。模型实际支持的参数以服务商为准。
- **保存并测试会实际生成一张测试图片，可能产生服务商费用**，最多等待约 3 分钟。测试图只在网页预览，不发微信群；通过后才保存，首个配置自动启用。切换已保存的生图配置不再额外调用测试。失败时保留原配置，启用中的配置需先切换才能删除。
- 生图与对话共用 AI 并发和每日调用额度；测试也计入全局额度，失败或超时可能已计费，不自动重试。密钥按原模型配置方式受本机 Windows 账户保护，页面不回显；编辑留空沿用该配置的密钥，更换地址须重新填写。

在已开启群功能与 **「@机器人问答」** 的群内，用另一个微信账号发送：

```text
@机器人 生图：一只坐在窗边的橘猫，温暖的水彩风格
```

只有已确认 @机器人的当前请求才可能调用生图模型。明确完整的 `生图：描述` 可直接生成；复杂绘图表达由当前启用的对话模型先判断意图并提取完整图片描述，再调用独立的生图模型。也保留“画图”“绘图”“画一只猫”“请画”“给我画”“绘制一幅图”等表达的识别。

| 消息示例 | 处理方式 |
| --- | --- |
| `@机器人 生图：一只猫`、`@机器人 一只猫，水彩风格，生图` | 调用生图模型 |
| `@机器人 帮我画一个图：一只猫`、`@机器人 画一张图，一朵花` | 调用生图模型 |
| `@机器人 画一只猫`、`@机器人 生成一张图片：夜景` | 调用生图模型 |
| `@机器人 生成一张小猫的图片`、`@机器人 生成星空壁纸` | 调用生图模型；支持主体放在“生成”和“图片/图像/插画/照片/壁纸/海报/头像”之间 |
| `@机器人 咖啡馆明天开业，做张海报，蓝底金字写“明天开业”，不要人物，竖版` | 语义提取主体、风格、配色、图中文字、比例与排除项后生成 |
| `@机器人 太暗了，亮一点，别改主体` | 结合本群同一成员最近成功发送的图片描述，重新生成；指代不足时追问 |
| `@机器人 不要生图，只教我写提示词`、`@机器人 解释“生成一张猫图”这句话` | 文字回答，不生成图片 |
| `@机器人 这张图片是什么`、`@机器人 这幅画很好看` | 普通文字问答 |
| `帮我画一个图`、`@其他人 生图：一只猫` | 不触发生图 |
| `生图 @机器人 你好` | 关键词在 @ 前，不触发生图，走文字问答 |

每条实时指令最多生成并回传一张图片，描述最多 8000 字。明确完整的生图指令和“生成一张小猫的图片”等简单请求可直接生成，不要求同时配置对话模型；复杂语境和多轮指代需要启用对话模型。意图识别会多一次对话模型调用，同样占用现有 AI 额度；识别结果不完整、超时或需求不明确时会停止生成并提示补充，不会猜测并调用生图接口。能力询问、否定、教程和引用会按文字问题处理。识别准确性取决于当前对话模型，仍可能需要追问。

图片上下文仅使用同一账号、同一群、同一成员最近成功发送的图片描述，以及该成员最近最多3条已确认问答中的提问（每条最多800字）。图片描述在进程内保留30分钟，最多100个成员上下文；发送失败不更新，重启后清空，`清空上下文` / `重置对话` 会同时清空本群的图片上下文。多轮修改按完整文字描述重新生成，目前不接收原图做像素编辑。用户要求的比例写入提示词，实际输出尺寸仍以管理页生图配置为准。

群/成员黑名单、账号校验、排队与回调去重沿用现有问答规则，生成图片不写入文字对话上下文。发送失败或结果不明不会自动重发。修改代码后重启 Python 服务，再刷新网页即可看到入口，无需退出微信。

配置保存在 `data/image-model.local.json`，纳入自动配置备份，可用 `WXHOOK_IMAGE_MODEL_CONFIG` 指定路径。生成图片保存在 `data/generated-images`（可用 `WXHOOK_IMAGE_OUTPUT_DIR` 指定），单张下载与转存 PNG 均限制 20 MiB，并校验静态图片可读性；远程图片 URL 仅允许公开 HTTPS 地址，本机免密服务可返回同源本机地址。图片下载不附带模型 API Key。下次生成时清理本目录中超过 24 小时的系统生成图片；停止生成时不会定时清理。生图目录同样受 `WXHOOK_MEDIA_MIN_FREE_MB` 的磁盘余量保护。

生图配置接口：`GET /api/manage/image-model` 查看状态，`POST /api/manage/image-models` 新增并测试，`PUT /api/manage/image-models/{ID}` 修改并测试，`POST /api/manage/image-models/{ID}/activate` 启用，`DELETE /api/manage/image-models/{ID}` 删除未启用配置。保存测试成功后才写入配置，接口不回显 API Key。

生图触发兼容 Hook 仅返回真实 @ID、正文省略 @显示文本的消息，也识别 @称呼后的零宽分隔符。真实 @ID 必须包含机器人账号；存在多个未知称呼、无法确认机器人 @位置时，会明确提示单独 @机器人，不会把该绘图请求转给文字模型。群“功能配置”显示服务版本、生图识别版本及最近一次 @请求的处理分支，并显示需求来自语义提取、直接指令还是关键词；机器人自己的回调和后续普通聊天不会覆盖这条请求诊断。

## 群内 @机器人问答：一条提问最多一条回复

在已启用机器人的群里，只有 @当前机器人账号的文字消息才进入问答；普通聊天、@其他人、仅 @所有人、
私聊和机器人自己发送的消息不触发。原来开启分享解析的群默认继承开启 @问答，
可在群“功能配置”中单独关闭“@机器人问答”，不影响分享解析；新发现且未启用功能的群不会自动答话。

打开网页管理端左侧 **「AI 模型」**（或群聊「功能配置 → 配置 AI 模型」），可查看已保存的模型列表，点击 **「添加模型」** 或 **「查看 / 修改」**，填写：

- **配置名称**：用于区分服务商、账号或不同模型，可选填。
- **Base URL**：服务商提供的 OpenAI 兼容接口地址，例如 `https://api.siliconflow.cn/v1`。
- **模型名称**：服务商支持的完整模型 ID。
- **深度思考**：硅基流动支持切换思考模式的模型可选择“关闭（优先快速回复）”，减少等待；其他服务或不支持该选项的模型请选择“跟随模型默认”。
- **API Key**：服务商密钥；本地免密模型可留空。已有密钥时留空沿用，更换 Base URL 时需要重新填写。

点击 **「保存并测试」** 后，后台自动向模型发送一条简短连接测试消息，页面显示成功结果和模型回复。
测试不会发送到微信群。可保存多个模型，选择一个首选，并按需要添加最多四个备用。第一个模型测试通过后自动成为首选，新增配置不会自动参与调用；
点击列表中的 **「设为首选」** 会再次测试，成功后切换后续群内 @问答，无须重启。修改当前启用模型测试通过后立即生效，
修改备用模型不影响当前问答。正在启用的模型需先切换到其他模型才能删除。连接失败、密钥无效、模型不可用、
额度不足或返回无效文本时显示原因，原有配置保持生效。接口须支持非流式 `POST /chat/completions`。
深度思考设置同时用于保存测试与实际群内回复；关闭时发送 `enable_thinking: false`，“跟随模型默认”不发送此参数。
参数说明见[硅基流动官方文档](https://docs.siliconflow.cn/cn/api-reference/chat-completions/chat-completions)。

### 军师模式

在已开启“@机器人问答”的群中，每次提问带上 `军师：` 或 `军师分析：` 前缀，使用现有对话模型提供情绪支持、关系分析和回复建议。也支持 `狗头军师：` 前缀。

```text
@机器人 军师：她说“最近有点忙”，这句话怎么回？
@机器人 军师分析：我们认识两个月，最近联系越来越少，我想判断是否继续主动。
@机器人 军师：刚才的建议我试过了，她答应周末见面，下一步怎么安排？
@机器人 清空军师上下文
```

微信引用：长按或右键一条消息，选择“引用”，再输入 `@机器人 军师：这句话怎么回？`，也可输入 `@机器人 军师分析：帮我分析这段话`。服务将当前提问与引用原文分开传给模型，并附上引用显示名；引用者不自动被视为提问者或恋爱对象。引用文字里的 @、军师指令、生图、提醒和清空命令不会触发工具。引用文本最多使用4000字，超出时标记为节选；引用另一条引用消息时只提取其可见回复，不展开深层聊天。

引用图片时，按引用中的原消息 ID 查找本群归档，并核对发送者，成功后交给视觉模型分析；不会拿最近的其他图片代替。找不到原图、来源群不符或来源成员被拉黑时会停止并说明原因。引用语音、视频、文件或链接卡片暂不读取，需改为提供文字或图片。引用文字本身不需要视觉模型。

截图分析：先发送聊天截图，再在同一群用同一个账号发送 `@机器人 军师：看看这张截图，该怎么回？`；也可在图片消息中 @机器人并附上军师指令。最近图片保留10分钟，截图分析需要配置视觉模型，或开启对话模型的图片理解。模型看不清文字或无法确认说话人时应先询问，不按左右位置猜测身份。

军师模式使用随安装包提供的狗头军师知识文档，每次按主题最多选3份，并限制资料与整体输入长度。不会联网搜索或自动翻查其他历史聊天；引用图片仅核验指定消息，不展开其他记录。不需要安装 Codex、ChatLab 或新的模型服务。普通提问仍进入普通问答；军师引用的“画图”“提醒”等文字不会触发其他工具。

军师短期上下文与普通问答分开，按机器人账号、群、提问成员和模型实例隔离，只保存已确认发送的文字问答，最多6轮、12000字；闲置30分钟或重启后清空，最多保留100个会话。独立视觉模型与对话模型使用各自的上下文，切换模型后开始新对话。截图字节不进入对话上下文。

`清空军师上下文`（也支持 `清空军师对话`、`重置军师对话`）只清空当前成员在本群的军师对话和最近图片，不影响其他成员或普通问答。原有 `清空上下文` / `重置对话` 会清空本群所有普通、军师及图片上下文。单独发送 `@机器人 军师` 可查看帮助。

本期没有长期关系档案；微信消息及机器人回复仍按现有聊天归档与数据保留配置处理。上下文隔离不会隐藏微信群消息，群内回复全群可见。军师请求复用现有模型服务商、备用顺序、额度及发送前权限检查；回答质量需在实际模型上验证。

知识文档固定自 [goutoujunshi](https://github.com/shengjidaguai-china/goutoujunshi/tree/6db7354a4002dc7c448a9c87ffdad8132570c9d3)，来源与 MIT 许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)。

### 图片理解（多模态）

打开 **「AI 模型 → 视觉模型 → 添加视觉模型」**，填写配置名称、Base URL、完整模型 ID 和 API Key。需要服务商支持 OpenAI 兼容的 Chat Completions 多模态 `image_url` 输入。视觉模型独立保存、独立设置首选和备用，普通文字问答仍使用对话模型。保存与切换首选时会发送一张内置红色色块图片测试图片输入，测试通过后生效，可能产生服务商费用；测试不会向微信群发送消息。

配置保存在 `data/vision-model.local.json`，纳入自动配置备份，可用 `WXHOOK_VISION_MODEL_CONFIG` 指定路径。视觉、对话、生图共用每日 AI 调用额度。未配置独立视觉模型时，仍兼容对话模型中原有的 **「支持图片理解（多模态）」** 配置。生图模型是独立的文字生成图片能力，不能用生图模型代替识图。

- 群成员发送图片并 @机器人：程序通过 Hook 的 `/GetMessagePic` 读取本地图片，校验后压缩为最长边 1600px 的 JPEG，作为多模态消息发送给视觉模型。图片没有附带文字时，默认请模型描述图片。
- 未 @机器人的图片不会主动回复，但会在本机按“账号 + 群 + 成员”记住 10 分钟。同一成员随后 @机器人 发送带视觉指代的问题（如“看看这张图”“我厉不厉害”“怎么样”“分析一下”）时，会自动带上最近这张图片；其他成员不能复用。
- 只把文字问答和模型描述写入本群上下文；图片本身不写入长期上下文，也不写入管理数据库。图片会发送给当前配置的模型服务商；不要发送不愿意给第三方的图片。
- 图片源文件上限 20 MiB，解码像素上限 4000 万，最长边 1600px，压缩后约 3 MiB；读取失败、格式不支持、图片超限或没有启用视觉模型时，只回复一条说明，不发送图片或重复扣额度。
- 图片请求的模型读超时为 100 秒，整条视觉备用链最多 180 秒；超时会提示检查网络、模型视觉能力或更换视觉模型。模型/搜索/生图请求会读取系统 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`；本机 Hook 请求仍不走代理。
- 图片请求优先使用独立视觉模型的首选与备用顺序；未配置时只在已开启图片理解的对话配置中尝试。纯文本模型不会被图片请求使用；未配置图片理解能力时，会提示到管理页添加视觉模型。
- 图片中的文字和画面都视为不可信资料；系统提示要求不执行图片内指令、不推断姓名/住址/联系方式等身份信息。模型仍可能出错，敏感图片请勿发送。
- 当前支持 Hook 回调的 `type=3` 图片消息；语音、视频、文件和表情包不会触发图片理解。

### 多个第三方配置按顺序切换

在 **「AI 模型 → 对话模型 / 生图模型 / 视觉模型」** 中，先保存并测试各服务商配置，再对需要自动接替的配置点击 **「加入备用」**。用 **「上移 / 下移」** 调整备用顺序，用 **「移出备用」** 停止该配置参与调用。页面显示完整的调用顺序，以及最近完成的一次调用实际使用的配置和各次失败原因。

- 每次新请求从首选开始，依次尝试备用 1、备用 2 等，首个成功结果即结束；同一次调用每个配置最多尝试一次，不轮询、不永久切换首选。
- 连接失败、超时、HTTP 408/429/5xx 后，该配置会短时跳过（默认约 20 秒），避免每个问题都重复等待同一个故障服务；其他配置成功即停止；若所有配置都在冷却中，仍会重新尝试而不是直接失败。管理页显示冷却剩余秒数，保存或切换配置会清空冷却。
- 对话模型的顺序用于普通问答、生图语义识别、总结等模型分析；生图模型和视觉模型各有独立的顺序。备用使用各自的地址、模型、密钥、思考设置或图片尺寸，密钥不在服务商之间复用。加入备用意味着故障时本次问题及所需上下文可发送给该服务商。
- HTTP 401/402/403/404/408/429、5xx 和连接失败会尝试下一项；HTTP 400 仅识别明确的余额/额度错误码（如 `insufficient_quota`、`insufficient_balance`），其他参数错误或内容拒绝停止。HTTP 200 中供应商自定义的余额错误文本不保证能识别。
- 对话超时、空文本、截断和语义识别 JSON 无效可尝试下一项；有效的普通聊天或追问判断不会因“未生图”而切换模型。联网搜索结果在一次问答的切换中复用，不重复搜索。
- 生图提交后读取超时、图片下载失败或返回无效图片，不自动重新生成，避免重复计费；收到明确的失败状态才按顺序切换。第三方即使返回 5xx 或超时也可能已经计费，实际收费以服务商为准。微信群发送失败仍不自动重发。
- 每次模型尝试均计入本地 AI 调用额度；本地额度用尽、群/成员权限变化或账号校验失败会立即停止，不通过备用绕过。整个对话调用最多等待 120 秒，生图调用最多 240 秒，超时后停止，可能尚未轮到全部备用。
- 服务商在响应中返回 `usage` 时，按北京时间、模型汇总输入/输出 token（`ai_tokens` 表，位于 `WXHOOK_AI_USAGE_DB`）；`usage` 缺失或格式异常只跳过统计，不影响回答。管理页“AI 用量”和 `GET /api/manage/ai-usage?days=7` 可查看。

备用顺序写入对应的本地配置并在重启后恢复。旧配置默认不启用备用。删除备用配置会同时移出队列；将备用设为首选会从备用队列移除该项，原首选需要手动加入备用。配置保存或测试失败时保留原配置；保存测试只测试正在编辑的那一个配置，不借助备用掩盖错误。手动改变对话调用顺序会重置对话模型实例；同一顺序内的自动切换保留当前群对话上下文。

管理 API：`PUT /api/manage/chat-model/fallbacks` 和 `PUT /api/manage/image-model/fallbacks`，请求体 `{"fallback_ids":["备用配置ID1","备用配置ID2"]}`；传空数组关闭备用。首选仍由原有 `/activate` 接口设置。状态接口返回 `fallback_ids` 与 `last_route`（仅配置 ID、状态和安全错误说明，不含密钥或提示词）。

模型配置保存在运行服务电脑的 `data/chat-model.local.json`，该目录被 Git 忽略；密钥不会返回给页面。
可通过 `WXHOOK_CHAT_MODEL_CONFIG` 指定其他本地配置路径。重启后自动恢复全部配置及启用项；旧版单模型配置会自动载入为启用项，
下次保存时迁移为模型列表。每个模型单独保存密钥，编辑时留空仅沿用该模型的密钥，更换地址须重新填写。请保护本机配置文件。

当前提问和历史提问均携带群内稳定的匿名成员标识，模型可区分“同一人的追问”和“其他成员的提问”；系统提示明确禁止把他人的姓名、身份或偏好归给当前提问者。标识按微信账号和群分别生成，不使用真实 wxid；身份缺失时标为 unknown，不能假定两个 unknown 是同一人。标识和 JSON 封装同样计入模型总输入长度上限。
只记录普通模型问答的原始提问和实际发送的回复，不读取整群历史；普通群消息、联网搜索摘要、连接测试、总结、报表、待办、提醒及失败/未确认发送的回复不会写入该上下文。当前被拉黑成员的历史问答，以及依赖这些历史生成的后续问答，不再转发。模型生成或发送前核验期间，历史涉及的成员被拉黑，则跳过该回答；若拉黑时发送请求已进入 Hook，无法撤回该请求，但该回答不会再写入上下文。模型请求仍受总输入长度限制，必要时丢弃最早的完整问答轮次。
历史在模型请求发出前重新读取和过滤，额度排队、搜索或账号核验期间发生的成员拉黑也会生效，不使用生成开始时的旧快照。

使用消息扩展字段中的 `atlist / at_list / atuserlist / at_user_list / atUserList` 或 `source / msgsource / msg_source`

微信的提及分隔空格 U+2005 同样支持。部分 Hook 的 `GetSelfProfile` 会返回有效 wxid 但昵称为空（`selfInfoMatched=false`），
此时无法只靠账号昵称识别 @。在群「功能配置 → 配置机器人群内显示名」填写 @时实际显示的名字，不含 @，每行一个。
保存后立即生效，无须重启；请使用另一个微信账号发送新的 @提问。页面同时显示识别到的称呼、
最近实时消息的处理状态及未触发原因。历史同步显示的消息不会触发问答。

群回调或历史记录的发送人为空或填成群 ID 时，若正文以 `成员wxid:\n` 或 `成员wxid:\r\n` 开头，会据此识别成员，供黑名单、问答、关键词规则、提醒和媒体处理使用。已有明确成员 ID 时不会被正文中的引用覆盖；归档保留原始回调字段。

不需要额外启动服务。可让群成员使用微信的 @ 功能发送 `@机器人 你好` 验证回复。

每个触发事件只生成一条最终回复，不发送“正在思考”等过程提示；超长回答截短为一条消息，不拆分发送。

## 群收藏与自然语言查找

管理页选中群聊后，打开 **「群收藏」**。收藏明确由成员命令或管理员添加，不会自动把每条聊天链接全部存入收藏。
群内使用需要开启全局 @问答以及本群 @问答，并遵守群开关、账号校验和成员黑名单；以下命令可以直接发送，也可以 @机器人后发送：

- `收藏 https://v.douyin.com/分享码/`：收藏这条分享。一次只处理一个链接。
- 先发送分享链接或卡片，再在 10 分钟内发送 `收藏`：收录本人在当前群之前发送的最近一条分享，不会取其他成员或其他群的链接。
- `收藏夹`：列出当前群最近的收藏。
- `搜索收藏：红烧肉` 或 `上次那个红烧肉教程在哪`：在当前群的标题、文案、标签、作者和备注中查找，返回收藏标题和原始链接。

抖音、小红书和 B站会使用现有解析配置获取文案、作者和图片/视频，并保存到独立收藏目录。
其他公开文章链接保存为书签，可填写标题、标签和备注；当前不抓取文章全文。标签根据文案中的话题和本地关键词生成，可手动修改。
同一群重复添加同一链接会返回已有收藏，不覆盖之前编辑的资料；不同群独立收藏。普通列表每页 20 条，每群最多 1000 条。

收藏记录写入管理数据库；媒体默认位于管理数据库旁的 `favorites/<收藏ID>/`，可用 `WXHOOK_FAVORITES_DIR` 指定目录。
媒体副本与普通分享下载独立，不随普通媒体保留规则或聊天记录保留规则自动清理。单文件沿用解析资源页的大小限制，单条收藏最多 500 MB。
解析或下载失败时仍保留原链接并显示“媒体未完整保存”，在卡片上点击 **「重试媒体」**；重试保留已编辑的标题、标签和备注。
管理员可在卡片中查看、下载、编辑和删除。删除收藏同时删除对应媒体副本，不删除原聊天消息。
现有自动备份包含管理数据库中的收藏文字资料，但不打包收藏媒体；迁移时应一并复制收藏目录。

默认搜索在本地运行。群内自然语言查找在已配置对话模型时会尝试扩展关键词；管理页点击 **「AI 扩展搜索」** 可使用同样能力。
该操作只把搜索句子发送给已配置模型，不发送其他群收藏，也不把整个收藏夹发送给模型；计入原有 AI 额度。
未配置模型、模型不可用或额度用尽时仍可使用本地关键词搜索。该功能不需要新的依赖，也不需要单独部署向量数据库。

### 保留的指定解析接口（仅抖音，可选）

需要使用原 `jk.y-l.cc` GET 接口时，在测试电脑打开 `/douyin`，选择“指定解析接口”，
将接口方提供的**完整地址**填入“完整接口地址”（以 `https://jk.y-l.cc/api/dsp/` 开头，含接口标识和用户 ID），
不要附加 `?url=` 参数，保存后立即生效。请求会自动以 `url` 查询参数传入群内分享链接。
接口地址含账号相关标识，只保存到本机 `douyin.local.yml`，仓库不包含你的实际地址；
也可用 `WXHOOK_DOUYIN_API_URL` 环境变量提供，环境变量在启动时优先读取。

该接口以 **`code=200`** 判断成功，成功示例中的 `status=101` 不作为失败处理。
视频读取 `data.url`，`data.down` 作为候选备用地址；图集优先读取 `data.pics`，为空时兼容 `data.download_image`。
封面 `data.cover` 不会被当作图集回传。图片数组支持 URL 字符串或含 `url`、`src`、`image_url`、`down` 的对象。
成功响应里没有可用媒体地址时仍会报错，不会显示虚假的解析成功。

接口连接失败、返回非 JSON、业务失败码或无效媒体地址都会进入原来的群内失败提示流程。
例如 `code=108`、`msg=会员接口不存在` 表示接口账号/地址当前不可用，需要接口提供方处理开通或更新地址。
API 模式失败时，如果配置了 media-parser 地址，会自动再尝试本地 media-parser 兜底；没有配置地址时保持原错误。
实际保存与回传的是接口返回的媒体文件，去水印和内容质量取决于接口提供方。

### media-parser 本地解析服务（可选来源与失败兜底）

[media-parser](https://github.com/ucmao/media-parser)（MIT）是独立的本地解析服务。
抖音使用无水印播放端点、小红书优先取原画、B站返回含音轨的 MP4，因此不再依赖第三方去水印接口。

安装只需一次：把 media-parser 克隆到 wxhook 项目目录的上一级（测试机 `D:\media-parser`，开发机 `F:\media-parser`）。
之后双击 `update-and-start.bat` 会自动安装依赖、停止旧进程、启动 media-parser，再启动 wxhook。
media-parser 启动失败或健康检查超时只会告警，不影响 wxhook 的其他功能。

在 `/douyin` 页面可以：

- 把“解析来源”选为 `media-parser（本地服务）`，直接用本地服务解析；
- 保持 `parse-video-py`、`指定解析接口` 或 `公开分享页` 时，主解析失败后自动再尝试 media-parser 兜底；
- 修改“media-parser 本地服务地址”（默认 `http://127.0.0.1:8051`）。地址只允许本机回环地址，留空表示禁用兜底；选择 media-parser 作为主来源时必须填写地址。

选择 media-parser 作为主来源时，它失败后不会再反向回退到 parse-video-py 或配置的指定解析接口。
小红书 Cookie 仍然只填写在 `parse-video.local.yml` 的 `xiaohongshu-cookie`，启动器会自动传给 media-parser，不需要复制到别处。

更新 media-parser：cd 到你的 media-parser 目录（测试机 `D:\media-parser`，开发机 `F:\media-parser`），执行 `git pull`，然后重启 wxhook。
日志在 `data/media-parser.stdout.log` 与 `data/media-parser.stderr.log`。
media-parser 的数据库与会话密钥保存在其源码目录，不进入 wxhook 的备份和更新。
如果修改端口，需要同时设置 `WXHOOK_MEDIA_PARSER_PORT` 和页面里的服务地址。

下载失败仍会清理未完成文件、重新解析并最多尝试 3 次（首次 + 2 次重试）；群/成员限制、文件大小上限等错误不会重试。
同一平台和源链接的媒体缓存 7 天；本次升级提升了缓存版本，旧缓存不会命中，第一次解析会重新获取媒体。
wxhook 只在抖音/小红书/B站链接上调用 media-parser；媒体回传仍走原有的群权限、大小限制和自动保存规则。
这里的“无水印”指选择平台的无水印媒体源，不做像素擦除，作者嵌入画面的水印仍会保留。

### 群内提示与自动回传

启用群聊解析后，默认会在**分享来源群**只发送文字“开始解析”，不附带任务编号或额外说明；解析或下载失败时发送失败原因。
下载完成后把媒体回传同一个群，成功结束不再发送文字提示。图片按图集顺序发送，全部 Hook 调用返回明确成功后资源页面才显示“已回传”。
开始提示失败不会阻止继续解析，所有提示的发送状态可在资源页面查看。

图片使用 `/SendImgMsg`；当前 Hook 文档没有独立的视频发送接口，因此视频通过 `/send_file_msg` 作为 **MP4 文件**发送，
不是原生视频消息气泡。WebP、AVIF 等静态图片生成 PNG 副本用于图片消息，原下载文件保留；动态图以原文件回传以保留动画。
图片转换使用 Pillow，更新这版后在测试电脑的项目虚拟环境执行一次 `python -m pip install -e .`，以后仍只运行 `main.py`。

在 `/douyin` 的默认设置中，可分别关闭“在来源群提示开始和失败”和“将视频或图片发回来源群”，保存后立即生效。
这些提示/回传设置应用于所有实际开启了解析的群；群的总开关、解析开关、自动保存开关和群/成员黑名单仍独立生效。
回传必须同时开启该群的自动保存。关闭自动保存或自动回传时，原因记录在资源页面，不另发结束提示，也不会把没有发送的媒体标为成功。

回传前、每个文件发送前以及图片转换后会检查群与成员限制。发送中遇到失败或超时即停止后续文件，
页面区分“解析失败”“部分回传”“回传失败”和“回传待确认”，并保留已经下载的文件。
发送超时可能已到达微信群，不自动重试；请先查看群聊结果。同一非零消息 ID 在当前运行和最近已持久化的任务记录中去重，
服务重启不会自动重发历史任务。自动提示不附带源分享链接，避免自己的回调再次触发解析。
可设置 `WXHOOK_DOUYIN_FEEDBACK_ENABLED=false` 并重启，临时关闭所有群内自动发送，保留解析下载功能。

运行 `main.py` 后，在测试电脑打开 **`http://127.0.0.1:8000/douyin`**，也可从群管理侧栏点击“资源”。
此功能与 Python 服务一起运行，不需要启动额外程序。

1. 先让目标群收到一条消息；配置页面的“最近收到消息的群”会显示该群 ID，点击可添加。
   也可以手动填写 `123456789@chatroom` 形式的真实群 ID，每行一个，不能使用群昵称。
2. 保留默认“parse-video-py”来源，勾选“启用群聊分享解析”，保留“解析成功后自动保存视频和图片”，点击“保存群配置”。
   默认名单保存后立即生效；空名单或未启用时不处理默认群，管理系统中已独立开启的群以单独配置为准。
3. 让群内成员发送抖音、小红书或 B站分享文案，也支持卡片 XML 中包含的链接。
4. 页面会依次显示“排队中 → 解析中 → 保存中 → 回传中 → 已回传”，展开记录可查看、播放、下载文件和查看每个文件发送状态。
   如果关闭自动保存，则只展示解析出的媒体链接。

默认文件位置为项目下 `downloads/douyin/<任务ID>/`：视频保存为 `001.mp4`，图集按顺序保存为
`001.webp`、`002.webp` 等（以实际文件格式为准）。`result.json` 记录作品标题、作者、来源群、发送人和文件列表。
页面显示最近 100 条记录，保留期限内的文件与结果记录重启后可继续查看；未完成的任务需要重新发送链接。
同一条回调重复推送不会重复创建任务，同一个链接在另一条新群消息中发送则会重新解析。

### 本地媒体自动清理

默认每天**北京时间凌晨 03:00**扫描整个媒体目录；服务启动时也会补清理已经过期的文件。
不需要额外启动定时程序，服务关闭期间不会执行删除，下次启动会补做。

| 类型 | 保留规则 |
|---|---|
| 全部媒体均已获 Hook 明确发送确认 | 任务结束后至少保留 24 小时 |
| 解析失败、未回传、部分回传、发送结果待确认、回传关闭 | 至少保留 3 天 |
| 解析记录 `result.json` | 任务结束后保留 30 天 |

达到期限后在下一次清理时删除，不会在发出文件后立即删除。
旧版本没有结束时间的任务，会按记录和媒体的最近写入时间保守计算；最近重新写入的媒体也会延后清理。
原始视频、图片、`send-*.png` 转换副本及遗留下载临时文件一起处理。
正在排队、解析、下载、回传的任务，以及正在通过资源页面播放/下载的任务，会跳过当前轮清理。
清理任务被取消时，会等待已开始的删除和清理状态更新结束后，再恢复文件读取；连续取消也不会使文件读取与删除重叠。
文件被占用或权限不足时记录失败原因，留待下一轮重试；文件清理后资源页显示“文件已清理”，不再生成失效的预览与下载链接。

清理扫描全部任务目录，不受页面最近 100 条的限制。只处理媒体目录下合法任务 ID 对应的本程序文件，
不递归删除目录，不跟随链接或 Windows 重解析点，不删除其他名称的文件。群配置、黑名单和聊天记录资料库不在清理范围内。
解析记录过期且媒体处理完毕后会删除记录；没有其他文件的任务文件夹随后移除。

可在 `douyin.local.yml`（没有该文件时使用 `douyin.yml`）设置后重启服务：

```yaml
cleanup-enabled: true
cleanup-hour: 3  # 北京时间，0–23
```

环境变量 `WXHOOK_MEDIA_CLEANUP_ENABLED=false` 可覆盖配置并关闭自动清理。
通过资源页保存群设置会保留这两项清理配置；页面展示清理规则、下次时间与上次释放的空间。

页面配置保存在被 Git 忽略的 `douyin.local.yml`，下载文件同样不会提交 GitHub。
未通过页面保存配置时，读取仓库中的 `douyin.yml`；也可直接编辑该文件后重启：

```yaml
enabled: true
groups:
  - '123456789@chatroom'
  - '987654321@chatroom'
auto-download: true
notify-group: true
send-results: true
parser-provider: parse_video
parser-config-version: 2
parser-api-url: '' # 仅选择旧 API 来源时需要
output-dir: downloads/douyin
max-file-mb: 100
```

存在 `douyin.local.yml` 时优先读取本地配置；也可以用 `WXHOOK_DOUYIN_CONFIG` 指定其他配置文件。
默认单文件最大 100 MB（配置范围 1–500 MB），每个作品总量最大 500 MB，图集最多 100 张，后台队列最多 50 个任务。
群消息接收不等待网络解析或媒体下载完成。对于沿用默认配置的群，禁用默认功能或移除群后会停止未完成的下载；独立配置的群需在管理系统中停用。
接口不可用或媒体下载失败时会显示原因，不会将网页错误内容保存为视频。内置解析模式下，公开页面需要登录验证、作品不可用或结构变化同样会报错。

相关接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `/api/douyin/config` | 查看或保存群名单、启用状态和自动保存设置 |
| GET | `/api/douyin/jobs` | 查看解析状态、媒体链接与本地文件列表 |
| GET | `/api/douyin/files/{任务ID}/{文件名}` | 播放或查看本地媒体，`?download=true` 下载 |

## 一键启动微信、Hook 和聊天页面

测试机已将 `version.dll`、`version.yml` 放在 `Weixin.exe` 同目录后，
只需在 PyCharm 中运行项目根目录的 **`main.py`**。
当前打开的 `src/wxhook_api/main.py` 也支持直接运行，`python -m wxhook_api` 同样使用一键入口。

首次使用请确认项目根目录 `launcher.yml` 中的微信路径：

```yaml
wechat-path: 'F:\app\Weixin\Weixin.exe'
open-browser: true
show-wechat-window: false
```

一键入口会启动 Python 服务，等待监听就绪后自动打开浏览器访问群聊管理系统；如果 Hook 尚未响应，则启动微信（已运行的微信会复用）。
微信自身加载旁边的 Hook DLL。程序在后台等待 Hook 和账号登录，登录后自动设置消息回调。
默认 `open-browser: true`、`show-wechat-window: false`，不主动恢复最小化或托盘隐藏的微信窗口，也不请求微信切换到前台。
如需自动唤起微信窗口，将 `show-wechat-window` 改为 `true`；如需关闭浏览器自动打开，将 `open-browser` 改为 `false`。
群管理地址为 `http://127.0.0.1:8000/`，消息工具为 `/messages`。
不再需要额外启动另一个 HTTP 服务或手动点击“启用消息接收”。Hook 断开、账号退出后会继续等待，恢复后重新设置回调。
扫码、确认登录仍需要在微信窗口中完成，等待期间聊天页面可以正常打开并显示启动进度。

停止 PyCharm 运行或在终端按 `Ctrl+C` 会关闭 Python 服务，微信保持运行。
如果 `8000` 已被旧版服务占用，请先停止旧服务后再运行一次。
如果对应的一键服务已经运行，再次启动入口会复用服务，按相同配置打开管理系统并决定是否唤起微信窗口。
启动器直接交由 Uvicorn 绑定端口，不再用额外的试绑定判断端口占用。
如果启动失败，控制台会保留原始系统错误；`netstat` 中只有 `TIME_WAIT` 不表示该端口有服务正在监听，
排查占用时应查看本地端口对应的 `LISTENING` 记录。
微信路径也可以通过 `WXHOOK_WECHAT_PATH` 环境变量覆盖。
一键启动用于 Python 和微信在同一台测试机的场景。

## 项目架构

服务由两个 HTTP 端点组成：

```text
业务调用方
    │
    ▼
FastAPI 桥接层  http://127.0.0.1:8000
    │
    │ HTTPX 转发
    ▼
现有 WeChat Hook 服务  http://127.0.0.1:30001
    │
    │ POST 消息事件
    ▼
FastAPI 回调入口  /receiveChatBotMsg
```

默认端口含义：

| 服务 | 默认地址 | 说明 |
|---|---|---|
| FastAPI 桥接层 | `127.0.0.1:8000` | 对外提供与文档一致的代理接口，并接收回调 |
| WeChat Hook 上游 | `127.0.0.1:30001` | 由现有 Hook 程序提供，FastAPI 不负责启动 |

FastAPI 层通过 `HookClient` 调用上游；一键入口负责打开已安装的 `Weixin.exe`，由微信自行加载其目录中的 Hook DLL。
Python 不直接加载或注入 `version.dll`，也不执行微信安装器 `weixin_4.1.10.27.exe`。

## 功能范围

当前桥接层提供：

- 配置文件和环境变量加载
- HTTPX 异步上游客户端
- 微信账号、媒体、消息、数据库、联系人和历史记录接口代理
- 上游 JSON、数组、扩展字段和 HTTP 状态码透传
- 消息回调接收与有界内存队列
- 回调处理器注册、最多四个会话并发分发与同一会话顺序处理
- 回调 URL 白名单校验
- 请求体大小限制
- 非法 JSON、上游超时、连接失败和非 JSON 响应处理
- FastAPI OpenAPI 文档
- pytest 契约测试和边界回归测试

自动回复、持久化回调收件、群聊/成员管理、AI 问答与生图、群工具、分享解析等业务能力见后续章节；它们都建立在上面的桥接层之上。

当前不包含：

- 微信进程 Hook 或 DLL 注入
- 图片、语音、数据库的底层解密算法
- 微信进程内 SQLite 实现
- 微信图片自动下载和语音转文字执行器（分享解析的媒体下载已实现）
- 多用户权限系统和公网部署配置（已提供本机访问边界及可选管理员口令认证）

`version.yml` 已加入 `.gitignore`，不要提交真实的 wxid、群 ID 或白名单。模板内容：


### 环境变量

可以复制 `.env.example` 作为配置参考。应用启动时读取环境变量，环境变量优先于内置默认值；原始 `version.yml` 不会被应用改写。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WXHOOK_CONFIG` | 项目根目录 `version.yml`（缺失时回退 `version.example.yml`） | YAML 配置文件路径 |
| `WXHOOK_HOST` | `127.0.0.1` | FastAPI 监听地址 |
| `WXHOOK_PORT` | `8000` | FastAPI 监听端口 |
| `WXHOOK_HOOK_BASE_URL` | `http://127.0.0.1:30001` | 上游 Hook 地址 |
| `WXHOOK_CONNECT_TIMEOUT` | `2` | 上游连接超时秒数 |
| `WXHOOK_READ_TIMEOUT` | `10` | 上游读取超时秒数 |
| `WXHOOK_MAX_BODY_BYTES` | `1048576` | HTTP 请求体最大字节数 |
| `WXHOOK_CALLBACK_QUEUE_SIZE` | `1000` | 回调内存队列容量 |
| `WXHOOK_CALLBACK_WORKERS` | `4` | 回调会话并发数，范围 1–4；同一会话保持顺序 |
| `WXHOOK_SHUTDOWN_TIMEOUT` | `5` | 服务关闭时 worker 回收超时秒数 |
| `WXHOOK_LOG_LEVEL` | `INFO` | Uvicorn 日志级别 |
| `WXHOOK_ALLOWED_CALLBACK_URLS` | 本机回调地址 | 允许 `/set_callback` 使用的 URL，多个地址用逗号分隔 |

默认回调白名单包含同一端口的 `127.0.0.1`、`localhost` 和 `[::1]`。监听 `::1` 或 `::` 时，启动器使用 IPv6 回环地址配置回调；显式设置白名单后仅使用指定地址。Hook 对 IPv6 的实际支持仍需在目标机验收。

Git Bash 临时设置示例：

```bash
export WXHOOK_HOOK_BASE_URL=http://127.0.0.1:30001

```

也可以使用 `.env.example` 中的变量作为本地环境配置参考，但不要把真实 Token、密码或私钥写入 `.env.example` 或 Git 仓库。

## 请求与响应约定

### 普通响应

消息和图片类接口通常使用：

```json
{
  "ret": 0,
  "retmsg": "success"
}
```

### PB 响应

文件消息等 PB 接口可能使用：

```json
{
  "ret": 0,
  "retmsg": "success",
  "data": {}
}
```

### QueryDB 响应

数据库接口通常使用：

```json
{
  "status": 0,
  "desc": "",
  "data": []
}
```

测试机提供的 Hook 中，`/QueryDB/GetAllDBName` 实际返回 `{"ret":0,"retmsg":"success","data":[{"dbName":"contact.db","dbHandle":123}]}`；其他版本也可能直接返回数据库数组，或使用 `status: 0` 包装。
自动同步同时兼容这些成功响应，以及 `ret: 0` 外层包装的 SQL `status: 0` 结果；出现任一非零错误码时仍按失败处理。
`/QueryDB/status` 返回 `IsLogin` 和 `hWeixin` 等字段。桥接原始接口保持响应透传，兼容处理只发生在管理系统内部。

仓库自带 Hook 的历史记录使用 `msgid / timestamp / type / content / sender / sender_nickname` 字段；同步器同时支持早期文档中的
`server_id / create_time / local_type / message_content / real_sender` 字段，保留消息 ID、原始时间、正文和发送人，并与实时回调去重。
同步失败时页面会指出失败阶段与 HTTP / Hook 状态码，便于区分数据库清单、SQL 查询和历史记录接口的问题。

### 响应透传

桥接层会保留：

- 上游实际 HTTP 状态码
- JSON 对象或数组
- 文档未定义的扩展字段
- 上游业务错误字段和错误码
- 字符串形式的大数 ID

不会把上游业务错误自动伪装成成功，也不会用过窄的 Pydantic 响应模型裁剪数据。

### 非法 JSON

客户端发送非法 JSON 或非法 UTF-8 时返回：

```json
{
  "ret": -1,
  "msg": "invalid json"
}
```

合法 JSON 但必填字段缺失或类型错误时返回 HTTP 422。`roomid` 可省略或为 `null`，统一转换为空字符串。

## 消息回调

Hook 推送到 `/receiveChatBotMsg` 的事件至少包含：

```json
{
  "event_type": 1001,
  "msgid": 191284230691951358,
  "type": 1,
  "timestamp": 1710000000,
  "wxid": "wxid_xxx",
  "sender": "wxid_xxx",
  "roomid": "",
  "content": "hello"
}
```

事件模型允许保留未定义的扩展字段，`msgid` 支持整数或字符串，以避免大数精度丢失。

### 回调处理流程

1. FastAPI 校验回调字段。
2. 事件进入有界内存队列。
3. 成功入队后立即返回：

   ```json
   {"ret": 0, "retmsg": "accepted"}
   ```

4. 最多四个后台消费者并发处理不同会话；同一会话保持顺序，单条事件的 handler 按注册顺序调用。
5. handler 异常只记录错误类型，不记录消息正文或异常详情。关键归档处理器失败时停止该事件的后续处理；其他事件继续处理。

队列满时返回 HTTP 503。回调落盘后才确认接收，未进入自动处理阶段的记录可在重启后恢复归档；已经进入自动处理阶段的记录不重放，不保证恰好一次投递。详见下方“长期运行与故障恢复”；重复事件不会仅因为 `msgid` 为 0 而被丢弃。

### 回调 URL 安全

`/set_callback` 只允许 `WXHOOK_ALLOWED_CALLBACK_URLS` 中的完整 URL：

- scheme 必须是 `http` 或 `https`
- 主机、端口和路径必须完全匹配
- 拒绝用户名、密码和 URL fragment
- 不允许任意外部 URL，避免 SSRF

## 联网搜索

在管理页「AI 对话模型」中可以配置 DeepSeek 联网搜索。开启后，每个 @机器人 的文本问题会先调用：

```text
POST https://api.deepseek.com/v1/tools/search
```

搜索结果的标题和摘要会作为参考上下文交给当前聊天模型，回复本身不附来源链接。搜索失败、超时或额度用尽时会自动回退到普通模型回答。

配置保存在本机 `data/search.local.json`，不会提交到 Git，也可以在模型弹窗中修改：

| 配置 | 默认值 | 说明 |
|---|---|---|
| 开关 | 关闭 | 是否对每个 @ 问题执行搜索 |
| Base URL | `https://api.deepseek.com/v1` | 实际请求 `/tools/search` |
| API Key | 空 | DeepSeek 搜索密钥，页面不会回显 |
| 每次结果数 | `5` | 范围 1–10，作为模型参考上下文 |
| 每日搜索上限 | `1000` | 按北京时间统计，跨天自动归零 |

计数规则：

- 请求前持久化预留次数；连接失败、超时、非 200、数据解析失败或请求取消均不退回，因为服务商可能已经处理并计费。次数不是账单金额统计。
- 达到当日上限后跳过搜索，直接使用普通模型回答，不会在群内额外提示。
- 使用单进程异步锁预留次数，避免并发请求超过上限。

DeepSeek 搜索按官方文档约 5 元/千次调用计费；每次 @ 问题还会产生原有的聊天模型费用。密钥可通过 `WXHOOK_SEARCH_CONFIG` 指向其他本机文件。

## 错误处理

| 情况 | HTTP 状态 | 响应 |
|---|---:|---|
| 非法 JSON / UTF-8 | 400 | `{ "ret": -1, "msg": "invalid json" }` |
| 合法 JSON 但参数错误 | 422 | `validation_error` |
| 回调 URL 不在白名单 | 422 | `callback_url_not_allowed` |
| 回调队列已满 | 503 | `callback_queue_full` |
| 上游连接失败或响应不可用 | 502 | `hook_transport_error` |
| 上游请求超时 | 504 | `hook_timeout` |
| 上游返回合法 JSON 的非 2xx | 保留上游状态码 | 保留上游 JSON |

上游返回的 `ret`、`status`、`msg` 或 `desc` 属于业务协议字段，不会被桥接层擅自转换成 HTTP 错误。

## 安全边界与限制

- 默认绑定回环地址 `127.0.0.1`，不建议直接暴露到公网。

- 执行真实消息发送、SQL 查询、获取密钥或修改上游回调前，请确认上游 Hook 已正确运行并了解操作影响。
- 默认仅信任回环地址的本机客户端，并校验 Host、Origin 和浏览器跨站请求标志。直接远程请求默认被拒绝；不要把可信本机入口通过无认证代理转发给其他人。
- 可设置 `WXHOOK_ADMIN_TOKEN`（至少 24 位随机 ASCII 字符）要求包括本机在内的管理访问认证。浏览器使用用户名 `admin`、密码为此口令；API 使用 `Authorization: Bearer <口令>`。口令不放入 URL、页面或日志。启动器自动携带口令；原生本机 Hook 的 POST `/receiveChatBotMsg` 可免管理认证提交回调，但不能读取记录或修改配置。
- 远程部署须设置管理口令和 `WXHOOK_ALLOWED_HOSTS`（逗号分隔主机名、不含协议与端口），并使用 HTTPS。反向代理须启用 TLS，仅信任指定代理提供的协议/客户端信息，限制后端端口只能由代理访问；即使代理转发至本机，也必须配置管理口令。本项目不提供多用户或逐群管理员权限。

### AI 调用与密钥保护

- 聊天、连接测试、日总结、周/月报及待办提取共享每日模型调用额度。默认全局 1000 次、每群 100 次、每成员每群 30 次；分别通过 `WXHOOK_AI_DAILY_LIMIT`、`WXHOOK_AI_GROUP_DAILY_LIMIT`、`WXHOOK_AI_MEMBER_DAILY_LIMIT` 配置，必须为正整数。连接测试和不属于群的管理调用也计入全局额度。
- 额度按北京时间跨天更新，保存在 `data/ai-usage.sqlite3`（可用 `WXHOOK_AI_USAGE_DB` 指定）。发请求前持久化预留，超时或失败不退还，因为服务商可能已经计费；额度无法落盘时停止模型调用。额度是次数限制，不是服务商账单的精确金额限制。
- 内置模型问答先原子预留一次模型额度，再执行搜索和生成；全局、群或成员的模型额度不足时不会继续搜索。同一提问的搜索与生成只预留一次模型额度；搜索期间取消或后续生成失败可能仍保留该次预留。
- 每次模型输入最多 24000 字符，群记录样本最多 16000 字符，保留最近的完整记录；输出请求上限为 `max_tokens=2048`。日总结显示实际采样条数。模型与搜索响应的传输内容和解压后内容分别限制为 256 KiB；用于识别模型额度不足的 HTTP 400 错误体分别限制为 16 KiB。支持 gzip / deflate（含原始 deflate），每次解压最多产出 64 KiB；截断、损坏或不支持的压缩格式会停止读取，不采用部分响应或用其触发备用模型。服务商仍需支持并遵守输出参数。
- 模型明确返回长度截断、内容过滤或工具调用等非正常结束状态时，结果不用于普通回复或保存总结、报表与待办；管理页或群内返回简短诊断，已有完整结果保留，不自动重试产生额外费用。兼容未提供结束状态的文本接口。
- 模型并发最多 2 个；群问答每群最多 3 个、每成员最多 2 个待处理问题（包含正在处理的请求），超过后在管理页标明限流，不发送额外刷屏回复。问答使用两个 worker，每群最多占用一个；同群保持顺序，其他群可使用空闲 worker。
- 总结、报表和提取任务将任务约束放入独立 system 消息，把群聊以 JSON 数据传入；模型输出不执行代码，AI 待办仍需核对保存。此隔离降低提示词注入风险，不能保证模型永远不受恶意内容影响。
- Windows 上的模型与搜索 API Key 使用当前用户的 DPAPI 加密保存，旧明文配置在成功加载时迁移。复制配置到另一台电脑或更换 Windows 账户后通常需要重新填写密钥；同一账户下运行的程序仍属于可信边界。非 Windows 环境使用临时文件的仅所有者访问权限，不提供 DPAPI 加密。
- 旧搜索配置中的空字符串或仅含空白的密钥按“未配置密钥”处理，迁移不影响启动，并保留原有用量；没有有效密钥时跳过搜索。
- 远程模型与搜索 Base URL 必须使用 HTTPS；HTTP 只允许 `localhost` 或回环 IP 的本机模型。旧的远程 HTTP 配置需要改为 HTTPS 后重新保存。
- 搜索配置写入成功后才会切换运行配置；保存失败保留旧配置。搜索额度写入失败会跳过搜索并继续普通模型回答，失败时可能保守保留一次搜索额度，避免误释放已使用额度。
- 搜索配置和用量全部校验成功后才启用搜索；计数损坏、日期异常或用量字段不完整时停用搜索并显示加载错误，不自动清零后继续请求，也不覆盖损坏文件。完全不含用量字段的旧配置仍可按首次使用迁移；其他错误请修复用量记录或明确重新配置后再启用。
- 模型、搜索配置及机器人群内显示名进入提交阶段后，即使保存请求被取消，也会等写盘和内存更新完成才释放配置锁，再向调用方报告取消；后续保存不会被旧的后台写入覆盖。写入失败则保持旧配置。请求取消后请重新打开配置确认实际保存结果。
- 群功能及群/成员黑名单修改在进入提交阶段后，同样会等待数据库事务和运行中缓存刷新完成，再报告请求取消；不会留下数据库已拉黑、机器人仍使用旧缓存的状态。
- 消息归档、成员同步、历史导入断点、回复去重和总结保存也会等已开始的事务结束后再处理取消，避免旧事务在后续更新之后落盘。账号校验即使被取消，已开始的数据库检查发现账号不一致时仍会暂停自动功能，直到服务重启。
- 群工具的待办、规则和提醒数据库操作开始后，请求取消会等待事务结束再释放资料库锁，避免后台写入与后续更新交错，使数量限制和更新顺序保持一致。取消后请刷新页面确认实际保存结果。
- 关键词规则编辑只更新当前群中仍存在的规则；并发删除先完成时，旧编辑请求返回“规则不存在”，不会重新创建已删除的规则。
- 媒体任务取消或服务停止时，会等待正在进行的任务记录写盘完成，再保存中断状态并释放清理保护；连续取消也不会让两次写盘交错，最终写盘失败仍会释放队列并显示存储错误。
- 自动周报/月报在等待生成锁后及模型请求出站前都会重新检查自动报表开关；关闭开关会停止尚未发出的自动请求，已发出的请求无法撤回。手动生成报表不依赖自动开关，仍遵守群总开关和黑名单。
- 自动发送在账号核验结束后、调用 Hook 前再次检查最新限制。问答、关键词规则、通知和媒体回传遵守各自开关及群/成员黑名单；提醒还会复核待办状态和提醒开关。核验期间被暂停或取消的发送记为“已跳过”，不会当作已发送或自动重发；已进入 Hook 的请求无法撤回。
- 每日待办汇总在账号核验结束后重新读取本次已占位的待办，仅发送当时仍符合到期条件的记录；已取消、手动完成或改到未来的事项会排除，标题和负责人使用最新值。整批已无有效事项时跳过发送，仍有效的其余事项正常汇总，不额外拉入未占位的新事项，也不自动重发该批次。

## 长期运行与故障恢复

2026-10-23 的稳定性更新需要停止原 Python 服务后重新运行 `main.py`；无需退出微信。首次启动会自动增加回调收件表，保留原有群策略与历史记录。

### 数据保留、全文搜索与存储统计

管理库现在使用 WAL，读查询走独立只读连接；管理页面轮询、词云、雷达和消息搜索不再占用回调写入使用的互斥锁。消息搜索优先使用 FTS5 trigram，3 个字符以上的查询走索引，1–2 个字符回退到原有 `instr`，SQLite 不支持 FTS5 时自动回退。首次升级到本版本时会对已有聊天记录建立一次 FTS 索引；历史库很大时启动会多花一些时间，之后不会重复建立。

默认保留策略是“聊天记录永久保留（需显式开启），终态回复凭据/待办/提醒按默认窗口清理”：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WXHOOK_CHAT_RETENTION_DAYS` | `0` | 聊天消息保留天数；0 表示永久保留 |
| `WXHOOK_CLAIM_RETENTION_DAYS` | `90` | 已完成的回复/关键词去重凭据保留天数；0 关闭 |
| `WXHOOK_TASK_RETENTION_DAYS` | `180` | 已完成/已取消待办保留天数；0 关闭 |
| `WXHOOK_REMINDER_RETENTION_DAYS` | `180` | 终态群提醒保留天数；0 关闭 |
| `WXHOOK_RETENTION_INTERVAL` | `86400` | 维护间隔秒数，最小 300 |
| `WXHOOK_FTS_ENABLED` | `true` | 使用 FTS5 trigram 消息搜索；设为 false 或 SQLite 不支持时回退 `instr` |

维护任务启动 5 秒后首次运行，之后按间隔清理；删除消息时 FTS 索引同步更新。管理页“连接与消息接收”显示管理库大小、消息数、回复凭据、待办和提醒数量。日总结、周报/月报保存在独立表中，不受聊天保留策略影响。

### 接收确认、重试与发送边界

`/receiveChatBotMsg` 在回调落盘后才返回 200。收件记录保存在当前 `WXHOOK_MANAGEMENT_DB` 的 `callback_receipts` 表，未完成记录的总数受 `WXHOOK_CALLBACK_QUEUE_SIZE` 限制，包含正在处理的记录。队列满、磁盘不可写或消费任务不可用时返回 503；是否重发仍取决于上游 Hook。

归档阶段遇到临时数据库或 Hook 故障最多尝试 3 次，间隔 1 秒、3 秒，同会话的后续消息等待该次处理结束，其他会话仍可并发推进。微信账号不一致会直接阻止处理，不自动重试。正常停机尽量完成已接收消息，超时留下的归档阶段记录在下次启动恢复。缺少有效消息 ID 的同一收件记录也有稳定归档键，恢复时不会重复入库；上游重新提交的无 ID 消息仍可能被当作另一条新消息。

收件尝试次数、自动处理阶段标记和最终状态的数据库写入遇到存储错误时，保留该消息及同会话顺序，以 1、3、10、30 秒间隔重试，随后每 30 秒检查一次；这些状态写入重试不消耗归档尝试次数，也不重放已经执行的自动处理。等待存储恢复期间 `/ready` 返回 503，新回调暂停接收；存储恢复后无需重启即可继续处理并释放收件容量。停机超时仍会停止等待，按原有阶段边界在下次启动恢复。

进入自动处理前先持久化阶段标记。已经进入这一阶段的消息在重启后不重放，避免重复模型请求、关键词回复或媒体发送。因此，进程在阶段标记保存后、自动处理实际开始前退出时，该条自动处理可能不执行；已加入各功能内存队列的任务也仍受各自原有停机规则约束。本更新没有承诺自动发送“必达”或跨进程恰好一次。终态收件记录清除正文，只保留最近约 1000 条元数据；聊天历史仍按原有规则保存在聊天表中。

群权限修改和权限快照读取在同一事务中完成，提交成功后再发布内存快照；读取或提交失败时保留原有策略，接口报告保存失败。

### 状态与日志

- `/health` 继续作为服务存活和版本检查，不访问 Hook。
- `/ready` 检查回调消费链和已启用后台任务的存活、恢复状态、账号暂停和队列无进展状态；不可用返回 503，不执行真实 Hook 或模型调用。任务仍运行但外部依赖不可用时，应同时查看同步和处理错误状态。
- `/api/callback/status` 与管理页“连接设置”区分已接收、处理完成、处理失败、排队与处理中数量，显示最近脱敏错误。处理计数是本次进程内计数，重启重新计数；持久化收件状态保留在数据库中。
- 通过 `main.py` 启动时默认将启动及应用错误日志写到管理数据库旁的 `wxhook.log`，单文件 5 MiB，加 3 份轮转副本。可用 `WXHOOK_LOG_FILE` 指定位置。直接使用外部 Uvicorn 命令时需要自行配置同等日志轮转。

### 磁盘空间和备份

媒体下载默认预留 1024 MiB 可用空间，可用 `WXHOOK_MEDIA_MIN_FREE_MB` 调整，设为 `0` 取消预留。下载前和数据块写入前检查空间；检查结果最多复用约 1 秒，并扣减本次已写入的字节。空间不足或存储盘不可用时停止新增下载、清理当前未完成文件并显示原因。释放空间后，新下载任务会重新检查；失败任务不会自动重发。这个保护是尽力预留，不是文件系统硬配额，不阻止其他程序消耗空间。

默认每 24 小时生成一次 ZIP 备份；没有近期备份时启动后生成，普通重启会复用近期备份。默认路径为管理数据库旁的 `backups`，同一数据库保留最近 7 份；旧文件占用或权限受限时可能暂时超过此数量。副本包含管理数据库、已存在的 AI 额度数据库，以及机器人、媒体、模型、搜索、启动器和 Hook 配置文件。小红书 Cookie 配置 `parse-video.local.yml`（或 `WXHOOK_PARSE_VIDEO_CONFIG` 指定文件）不纳入自动备份，迁移后请在目标机器单独配置；旧版本生成的 ZIP 可能仍含 Cookie，本次修改不会清理或改写旧备份，请勿公开分享。不打包下载媒体，也不导出进程环境变量。各数据库和配置分别取得一致副本，不是所有文件的同一时刻全局快照。备份包含聊天与配置，应放在受保护的位置；Windows DPAPI 密钥仍需原 Windows 用户环境才能解密。

数据库通过 SQLite 在线备份复制，执行 `quick_check` 和 ZIP 完整性校验，成功后才发布和轮换。备份失败保留已有可用副本并每分钟重试；轮换只处理本数据库生成的完整备份文件。备份还会预留至少两倍源数据库大小的临时空间和默认 1024 MiB 剩余空间。

快照生成与旧文件清理分别报告结果。单个旧备份无法删除时继续清理其他超额副本，管理页显示清理警告；最新快照仍记录为成功。清理每分钟独立重试，不因已有近期备份而跳过，也不为重试清理而额外生成新快照；文件可删除后自动恢复保留数量。

普通重启复用近期备份时，校验 ZIP 完整性、管理数据库条目和清单后恢复最近备份时间及文件名，管理页会继续显示最近备份。轮换先确认有足够的新副本通过校验，才删除更旧的文件；损坏或不可读取的副本不占用有效保留份数，因此文件总数可能暂时超过配置值。最新文件未通过校验时立即尝试补建，失败后每分钟重试，并保留旧的有效副本。文件身份、大小或修改时间变化后重新校验，正常状态刷新复用校验结果，不会额外生成备份。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `WXHOOK_BACKUP_ENABLED` | `true` | 自动备份开关 |
| `WXHOOK_BACKUP_INTERVAL` | `86400` | 备份间隔秒数，至少 300 |
| `WXHOOK_BACKUP_KEEP` | `7` | 保留份数，1～30 |
| `WXHOOK_BACKUP_DIR` | 数据库旁的 `backups` | 备份位置，可选其他磁盘 |
| `WXHOOK_BACKUP_MIN_FREE_MB` | `1024` | 备份磁盘预留空间 |

恢复时先停止 Python 服务，将 ZIP 解压到独立目录，检查 `manifest.json` 和数据库 `PRAGMA quick_check`；验证后按清单还原数据库与对应配置。恢复到同一微信账号，先核对群开关、黑名单和发送状态，再启动服务。不要把原数据库与别的时间点留下的 `-wal`、`-shm`、`-journal` 文件混用；建议先在独立目录验收恢复副本。同磁盘备份不能覆盖物理磁盘损坏，可用备份目录设置保存到其他磁盘。

### 部署与进程恢复

Windows 上双击项目根目录的 **`update-and-start.bat` 即可一键更新并重启**，不必先手动关闭旧黑窗口。脚本按 5 步顺序执行：更新代码 → 准备依赖（此时旧服务仍在运行）→ 停止旧 wxhook 服务 → 停止旧 media-parser 并启动新实例（失败只告警，不阻止后续启动）→ 启动新 wxhook 服务，并核对新服务的健康状态和代码版本。media-parser 的启动输出与错误分别保存在 `data/media-parser.stdout.log` 与 `data/media-parser.stderr.log`。

| 需求 | 操作 |
| --- | --- |
| 更新代码并自动重启 | 双击 `update-and-start.bat` |
| 只重启当前本地版本 | 双击 `start-local.bat`，或执行 `.\update-and-start.bat --local`，跳过 Git 更新，自动停止旧进程后启动 |

GitHub 无法连接或依赖、配置检查失败时，脚本停止并保留旧服务运行，不会先杀掉旧服务。只需重启时可使用 `start-local.bat`。使用 Git bundle 离线更新也不会更改 `origin`，后续仍可正常从原仓库拉取；在项目目录运行 `git pull --ff-only .\更新包文件名.bundle main` 成功后，使用 `start-local.bat` 自动重启，避免再次联网更新。

拉取失败时，更新窗口保留 Git 原始输出，并补充中文原因；本地改动或同名未跟踪文件阻止更新时，逐项列出文件路径和类别。错误摘要保存在 `data/update-last-error.log`，只含时间、项目目录、原因和文件名，不包含文件内容或 Cookie，可复制摘要进行排查。网络、认证、分支分叉和 Git 锁定会分别提示，不会被当作文件冲突。脚本不会自动清理或覆盖本地改动；错误日志为最近一次失败记录，请核对时间。

重启控制由 `scripts/restart-project.ps1` 执行，按项目路径识别 Python 进程，并核对 PID、创建时间和命令行；不会批量结束所有 Python，不会退出微信。新版服务通过本机文件请求正常退出，最多等待45秒；旧版或无响应的已确认项目进程会被强制结束。无法确认归属的进程不会被结束，端口仍被占用时会报错并停止。连续双击使用项目级互斥锁，已有重启任务执行时不会再次启动。通过其他 Python 环境以相对路径手动运行的旧版本，可能无法确认归属，此时仍需在原窗口停止一次。

启动成功后服务在后台运行，启动窗口可关闭；浏览器是否自动打开仍遵循 `launcher.yml` 的 `open-browser`。启动输出保存在 `data/startup.stdout.log` 与 `data/startup.stderr.log`，应用运行日志仍在配置的日志文件中（默认 `data/wxhook.log`）。旧版黑窗口可能留下已停止的提示，但原 Python 服务已结束，不会重复占用端口。

两个入口共用依赖检查：首次运行会安装依赖，之后仅在 `requirements-runtime.lock` 或 `pyproject.toml` 变化时重新安装，并在每次启动前运行 `pip check`。因此，本地启动也需要已安装匹配的依赖；首次安装或依赖文件变化时仍可能需要访问软件源。没有虚拟环境时需要已安装 Python 3.12。脚本默认设置常规同步间隔为 180 秒，已有 `WXHOOK_SYNC_INTERVAL` 环境变量时保留其值。Git、依赖或启动失败会保留报错窗口；使用前确认本机 `launcher.yml` 的微信路径与 Hook 文件配置正确。脚本不自动覆盖或丢弃本地修改；本地修改阻止更新时，需要先处理 Git 提示。计划任务管理的服务应通过计划任务重启，避免其自动恢复策略与手动重启同时生效。

提供 [部署依赖快照](requirements-runtime.lock)，来自本轮 Windows / Python 3.12.14 的已验收运行环境，固定 54 个运行时依赖；开发测试依赖仍由 `.[dev]` 提供。在新虚拟环境中安装：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-runtime.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m pip check
```

升级前保留数据库和配置备份，在独立环境验证后再切换。该快照面向上述 Windows / Python 版本，不保证其他平台完整通用。

[计划任务安装脚本](scripts/install-startup-task.ps1) 可配置当前用户登录时启动服务，并在进程失败后间隔一分钟重启，最多三次；同一计划任务不并行启动第二份，正常退出不因该失败策略立即重启。脚本只交付文件，本轮没有安装系统任务。部署机决定启用时执行：

```powershell
.\scripts\install-startup-task.ps1 -WhatIf
.\scripts\install-startup-task.ps1
# 移除时：.\scripts\install-startup-task.ps1 -Remove
```

需要当前用户保持登录供微信工作。计划任务只托管进程，不保证发现“进程活着但业务不可用”的故障；此类情况查看 `/ready` 与管理页诊断。PyCharm、终端与计划任务避免同时管理同一服务。项目不会自动读取 `.env`；计划任务使用其启动时可见的环境变量。

大历史库下的统计查询已改为 WAL + 独立只读连接，不再与回调写入共用互斥锁；本轮仍未在目标机完成 24～72 小时连续运行验收，部署后仍需测量实际磁盘增长、查询等待、队列深度，并验证断网、微信登出、Hook 重启及备份恢复。
