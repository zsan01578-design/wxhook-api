## 四路回调并发优化（2026-10-22）

用户希望进一步利用四核四线程机器的空闲处理能力。本轮确认原先全部回调共用一条串行处理链，任一群等待 Hook 账号核验或其他异步操作时，会延迟其他群。现在在一个服务进程内默认启用四条异步消费链，并按会话选择最早可处理的消息；一个群的积压不会占住其他消费链。同群及同一私聊仍按入队顺序完成全部处理器，群号位于 `roomid` 或 `wxid` 的回调共用排序键。关键归档失败仍跳过该消息的后续自动处理。

保留全局有界等待队列，正常停机处理已接受事件，超时和重复取消时收尾全部消费者并清空遗留事件，重启不重放。新增 `WXHOOK_CALLBACK_WORKERS`，默认 4，限制 1–4；设为 1 可恢复全局串行。该值是异步消费链数，不是 OS 线程数；本轮没有增加服务进程、AI 调用并发或媒体下载并发，也没有放宽 SQLite 写入锁。

并发边界检查还复现了已排队归档在等待数据库锁期间被暂停账号、取得锁后仍继续写入的问题。新增回归在修复前失败；现在获得写入锁后再次检查账号暂停状态，拒绝该写入，避免并发中账号变更保护失效。

新增 `tests/test_callback_concurrency.py` 的 20 项测试，覆盖四个会话同时推进、同群积压与顺序、群号来源兼容、关键/普通处理器异常、四消费者取消收尾与重启、单路回退、配置边界、应用真实归档流程配合模拟 Hook，以及等锁期间账号暂停。相关分组 **77 项通过**。
